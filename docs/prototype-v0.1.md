# 인수인계서 AI — 웹 프로토타입 v0.1

> 2026-11-18 작성. 2026-11-11 팀 회의에서 정한 세 축(작성 가이드 · 후임자 관점 꼬리질문 · 약관·법규 검토)을
> 실제로 눌러 볼 수 있는 웹 화면으로 옮긴 1차 버전입니다. 공개 자료와 가상 데이터로만 만들었습니다.

## 1. 이번 버전의 목표

- 회의에서 정한 기능을 **화면에서 끝까지 한 번 돌려 볼 수 있게** 만든다.
- API 키가 없어도, 인터넷이 없어도 **그 자리에서 시연**된다.
- 나중에 사내 LLM·사내 시스템으로 바꿔 끼울 수 있게 **경계를 나눠** 둔다.

## 2. 4단계 화면

| 단계 | 하는 일 | 화면에서 보이는 것 |
| --- | --- | --- |
| 1. 시작 | 기존 초안 업로드(`.hwp` `.hwpx` `.docx` `.pdf` `.txt`) 또는 붙여넣기, 없으면 표준 틀에서 시작 | 파일 판독 결과·경고, 12개 항목 작성 가이드, 개인정보 가림 미리보기 |
| 2. 빈틈 점검 | 초안을 12개 항목 기준으로 점검하고, 빈 곳을 겨냥한 후임자 관점 질문을 던짐 | 항목별 커버리지 막대, 질문 카드(이유·근거 인용·예시), 답변 입력, 미답변/건너뜀 추적 |
| 3. 약관·규정 근거 | 초안 문장마다 근거가 될 조항을 찾아 조문 번호·쪽수와 함께 표시 | 규정 선택(내장 기본공급약관) 또는 PDF 업로드, 후보 조문 카드, 신뢰도, 원문 펼치기 |
| 4. 내보내기 | 표준 항목 순서로 정리한 인수인계서 + 아직 답하지 못한 질문 목록 | 문서 미리보기, `.md` / `.txt` 내려받기, 복사 |

### 2단계가 "규칙 기반"인 이유

질문 생성은 LLM 없이도 돌아가야 한다고 보고 **항목별 신호(signal) 기반**으로 설계했습니다.

- 12개 항목마다 "이 항목을 제대로 적었다면 문서에 나타날 표현"을 정해 두고(예: 정기 업무 → 주기, 마감일, 산출물, 제출 채널),
  비어 있는 신호를 그대로 겨냥해 질문을 만듭니다. `예외 상황이 없습니다`가 아니라
  `민원이 반복될 때 어디서 판단이 갈리는지`를 묻습니다.
- `상황에 따라`, `담당자에게 문의`, `대부분` 같은 **모호한 표현은 그 문장을 인용해 되묻습니다**.
  이런 문장만 있는 항목은 "채워진 것"으로 세지 않습니다.
- 답변을 적으면 그 신호가 채워진 것으로 다시 계산해 **초안 기준 → 답변 반영 커버리지**를 함께 보여 줍니다.
- LLM을 붙이면(선택) 같은 결과에 질문 몇 개를 더 얹습니다. LLM이 실패하면 규칙 결과만 남고 화면에 안내가 뜹니다.

## 3. 약관 조항 매칭 방식

1. **업로드 시점에 조문 파싱** — 규정 PDF를 받으면 목차에서 조문별 인쇄 쪽수를 읽고, 본문에서
   `제 N 조 (제목)` 경계로 잘라 `조문 번호 · 제목 · 장 · 쪽수 · 항(①②…)`를 붙인 단위로 색인합니다.
   조문 구조를 못 찾는 PDF는 페이지·문단 블록으로 대체하고 그 사실을 화면에 알립니다.
2. **문장 단위 대응** — 초안을 문장으로 끊고(머리말·날짜 줄 제외) 조문 단위와 비교합니다.
   점수는 ㉠ BM25(단어 겹침, 긴 조문에 불리하지 않게) ㉡ 조문 제목 일치 ㉢ **업무 용어 사전**(계약전력·공급정지·이의신청 등)
   ㉣ **동의어 사전**(문서의 `명의변경` ↔ 약관의 `전기사용계약자의 변경`)을 합산합니다.
3. **억지로 붙이지 않기** — 업무 용어도 없고 뚜렷한 단어가 하나뿐이면 후보에서 뺍니다.
   점수가 낮으면 신뢰도 `낮음`으로 표시하고, 문장에 걸리는 조문이 없으면 아예 표시하지 않습니다.
4. **표시** — `제74조의2 (요금에 대한 이의신청) · 59쪽 · 제8장` 처럼 원문 위치와 발췌, 일치한 단어를 함께 보여 주고,
   다른 후보 조문도 접어서 제공합니다. 화면과 문서 모두에 "법적 판단이 아니라 확인 보조"라는 문구를 넣습니다.

## 4. 개인정보 가림과 LLM 연결

- **가림**: 주민등록번호·휴대전화·일반전화·이메일·사업자등록번호·계좌·카드번호를 정규식으로 찾아 `[휴대전화]`처럼 치환합니다.
  원문은 화면·내보내기에 그대로 남고, **LLM에 보내는 사본만** 가립니다. 무엇이 몇 건 가려졌는지 미리보기로 보여 줍니다.
- **LLM 어댑터**(`app/llm.py`): `LLM_PROVIDER=demo|openai|ollama`로 전환합니다.
  - `demo`(기본): 외부 호출 없음. 화면 상단에 "입력한 내용은 외부로 전송되지 않습니다" 표시.
  - `openai`: `LLM_BASE_URL`(기본 `https://api.openai.com/v1`), `LLM_MODEL`, `LLM_API_KEY`.
  - `ollama`: `LLM_BASE_URL`(기본 `http://localhost:11434`), `LLM_MODEL`. 사내망·온프레미스 시연용.
- 핵심 판단(빈틈 탐지·조문 매칭)은 LLM 없이 동작하고, LLM은 질문을 더하는 보조로만 씁니다.

## 5. 파일 형식별 처리

| 형식 | 방법 | 남는 한계 |
| --- | --- | --- |
| `.pdf` | PyMuPDF가 있으면 우선, 없으면 pypdf. 페이지별 텍스트 보존 | 스캔 이미지 PDF는 OCR 없이는 못 읽음(안내 표시) |
| `.docx` | python-docx. 본문·표를 문서 순서대로, 제목 스타일은 `#`로 살림 | 머리글·각주·이미지 안 글자는 제외 |
| `.hwpx` | zip 안의 `Contents/section*.xml`(OWPML)을 직접 파싱. 문단은 줄, 표는 행(`|`) | 이미지·개체 내부 글자는 제외 |
| `.hwp` | 한글 5.0 CFB 컨테이너를 `olefile`로 열고 `BodyText/SectionN` 레코드(HWPTAG_PARA_TEXT)를 직접 해석. 압축(zlib) 해제 지원 | 글자만 추출(서식·표 구조 손실). 암호 문서는 거부 |
| `.txt` / `.md` / 붙여넣기 | UTF-8 우선, 실패 시 cp949/euc-kr 추정 | — |

## 7. 알려진 한계 / 다음 단계

1. **규칙 기반 질문의 한계** — 신호 표현이 문서에 없으면 "빈 곳"으로 봅니다. 표현이 다른 좋은 내용은 놓칠 수 있어
   LLM 보조와 사람 검토를 전제로 합니다.
2. **조문 매칭의 한계** — 형태소 분석 없이 단어·사전 기반이라, 같은 뜻의 다른 표현은 동의어 사전을 계속 보강해야 합니다.
   그래서 결과를 "근거 후보"로만 제시합니다.
3. **표·서식** — `.hwp`는 글자만, `.hwpx`는 표를 행 텍스트로 폅니다. 서식 그대로 되돌려 주는 기능은 없습니다.
4. **업로드한 규정은 메모리에만** 저장됩니다(프로토타입). 서버를 다시 켜면 사라집니다.
5. **다음 단계 후보** — 질문 체크리스트를 오픈소스 표준으로 공개, 인수인계서 품질 점수 정의, 사내 규정 여러 개 동시 색인,
   근거 조항 개정 감지(약관 버전 비교), 2단계 답변을 초안 본문에 직접 반영하는 편집기.

## 8. 실행

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python run.py            # http://127.0.0.1:8000
python -m pytest tests   # 테스트
```

환경변수로 LLM을 붙일 때:

```bash
LLM_PROVIDER=openai LLM_MODEL=gpt-4o-mini LLM_API_KEY=... python run.py
LLM_PROVIDER=ollama LLM_MODEL=llama3.1 LLM_BASE_URL=http://localhost:11434 python run.py
```
