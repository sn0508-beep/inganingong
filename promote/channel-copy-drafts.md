## A. 커리어리(직장인 커뮤니티) — 긴 글

**언제:** 3주차. 체크리스트 공개본이 완성된 직후.
**목적:** 제품 홍보가 아니라 **문제 검증**. "빠지는 항목"에 대한 실무자 경험을 받는 것.

### 제목 후보 (하나 선택)
1. `인수인계서에서 실제로 가장 많이 빠지는 항목, 체크리스트로 정리해봤습니다 (공유)`
2. `담당자 바뀔 때 후임자가 제일 먼저 막히는 것 — 인수인계서 체크리스트 공유`
3. `인수인계서를 "후임자 관점 질문"으로 점검하는 도구를 만들고 있습니다 (체크리스트 무료 공유)`

### 본문

```
안녕하세요. 한양대에서 「인간-인공지능협업제품서비스설계」 수업 팀 프로젝트로
인수인계서를 돕는 AI 도구를 만들고 있는 학생 팀입니다. (팀원 4명, 5주 과제)

먼저, 만들고 있는 것과 별개로 정리한 체크리스트를 공유합니다.
지금은 구현 전 단계라 제품은 없고, 문서만 있는 상태입니다.

▶ 인수인계서 품질 체크리스트 (후임자 관점)
{{ 체크리스트 링크 — GitHub 문서 URL }}

[왜 이걸 만들게 됐나]
{{ 팀원이 실제로 겪은 상황 1~2문장. 경험담이 없으면 "회의에서 나온 문제 제기"로 서술 }}
인수인계서는 서식에 정해진 칸을 채우는 방식이라, 정작 후임자가 첫 주에 막히는
지점 — 예외 상황, 승인 권한, 연락 순서, 작년에 한 번 터졌던 문제 — 이 빠지기 쉽습니다.
문서가 부실하면 후임자는 같은 시행착오를 처음부터 다시 겪습니다.

[만들고 있는 것]
작성된 인수인계서 초안을 넣으면 AI가 후임자 입장에서 꼬리질문을 던지고,
정리된 문서와 함께 "아직 답하지 못한 질문 목록"을 내놓는 도구입니다.
① 작성 가이드라인 ② 후임자 관점 꼬리질문 ③ 약관·법규 근거 확인(검토 보조,
법적 판단을 확정하지는 않습니다) 세 가지가 축입니다.
회사 자료는 쓰지 않고, 전부 가상 인수인계서로만 시연합니다.

[부탁드리는 것 — 두 가지만]
1. 체크리스트를 보시고, 실제로 빠져 있거나 틀린 항목을 알려주세요.
2. 최근 인수인계를 주고받으셨다면, "이게 제일 안 적혀 있었다" 한 가지만 적어주세요.

그 한 줄이 체크리스트 항목이 되고, 4주차에 만들 시제품의 질문이 됩니다.
반영한 내용은 저장소에 커밋으로 남기고, 어떤 피드백이 반영됐는지도 함께 적겠습니다.

▶ 저장소: {{ 저장소 URL }}
※ 아직 코드가 없는 단계입니다. 진행 상황은 README에 계속 갱신합니다.
```

**주의:** 댓글로 "우리 회사는 이렇게 한다"가 나오면 **회사명·부서명은 본문에 옮겨 적지 않는다.** "어느 공기업" 정도로 익명화.

## B. 링크드인 — 짧은 소개글

**언제:** 3주차부터 주 1회. 팀 계정 또는 팀원 개인 계정.
**목적:** 만드는 과정의 공개 + 공공·HR 담당자와의 접점.

### B-1. 1회차 (체크리스트 공개)

```
인수인계서는 왜 늘 부실한 채로 넘어갈까요.

서식에 정해진 칸은 채우기 쉽지만, 후임자가 첫 주에 실제로 막히는 것 —
승인 권한, 예외 처리, 연락 순서, 1년에 한 번 있는 일 — 은 칸에 없습니다.

팀 프로젝트로 이 문제를 다루는 도구를 만들고 있습니다.
작성된 초안에 후임자 관점의 꼬리질문을 던져 빈틈을 끌어내는 방식입니다.

첫 산출물로 "인수인계서 품질 체크리스트"를 공개합니다. (6개 영역 46개 항목, 후임자 질문 기준)
{{ 링크 }}

아직 구현 전 단계이고, 회사 자료 없이 가상 사례로만 검증합니다.
공기업·공공기관에서 인수인계를 해보신 분의 의견을 특히 듣고 싶습니다.
"이 항목이 제일 안 적혀 있었다" — 한 줄이면 충분합니다.

#인수인계 #업무문서화 #공공기관 #AI
```

### B-2. 2회차 (4주차, 시제품 공개)

```
3주 전에 공유한 인수인계서 체크리스트에 달린 의견 중
{{ n }}가지를 문서에 반영했습니다. (반영 내역: {{ 커밋/문서 링크 }})

이제 초안을 넣으면 실제로 꼬리질문이 나오는 시제품을 공개합니다.
{{ 링크 }}

여전히 한계가 분명합니다. 법규 검토는 근거 조항을 짚어주는 수준이고,
문서에 없는 사실을 만들어내지 않도록 일부러 보수적으로 답하게 했습니다.
그래서 "이 질문은 의미 없다"는 지적이 오히려 도움이 됩니다.
```

**주의:** 링크드인은 게시 빈도가 잦으면 노출이 줄어든다. 주 1회, **내용이 바뀔 때만.**

## C. 짧은 채널 — 교내·오픈채팅·1:1

### C-1. 에브리타임 / 교내 (3주차)

```
[한양대 수업 팀프로젝트] 인수인계서 AI 만드는 팀입니다.
공기업·공공기관 인수인계 담당이었거나 후임자로 받아보신 분,
혹은 부모님·지인이 해당되시는 분 계신가요?

인수인계서에서 "이게 제일 안 적혀 있었다" 한 가지만 알려주시면
체크리스트에 반영하겠습니다. 20분 정도 인터뷰도 가능합니다.
▶ 체크리스트: {{ 링크 }} / ▶ 댓글 또는 쪽지 주세요.
```

### C-2. 1:1 요청 메시지 (카톡·DM, 4주차 테스트 요청)

```
{{ 이름 }}님, 안녕하세요. {{ 관계 }} 최선주입니다.
수업 팀 프로젝트로 인수인계서 점검 도구를 만들고 있는데,
실무 경험이 있는 분께 한 번만 봐주시길 부탁드리고 싶어서 연락드렸어요.

회사 자료는 전혀 필요 없고, 저희가 만든 가상 인수인계서(공기업 정기 계약 업무 샘플)로만
20분 정도 화면 공유하면서 써보시면 됩니다.
"이 질문은 실제로 안 물어볼 것 같다", "이 항목이 더 중요하다" 정도만 말씀해주시면 충분해요.

혹시 괜찮으시면 이번 주 {{ 요일 }} 저녁이나 주말 중 편한 시간 알려주세요.
바쁘시면 체크리스트만 보고 한 줄 남겨주셔도 정말 도움이 됩니다.
▶ {{ 체크리스트 링크 }}
```

**주의:** 1:1 메시지에서 **상대 회사 자료를 요청하지 않는다.** 부탁은 "의견"이지 "자료"가 아니다.

## D. GeekNews — Show GN

**언제:** 4주차. **실제로 입력→질문→빈틈 목록이 동작한 뒤에만.**
**규정 요약(2026-11-18 확인):** 직접 만든 것만, 다른 사람이 바로 써볼 수 있어야 함(랜딩·예약 페이지 불가), 만든 사람이 직접 등록, 지인에게 업보트·댓글 요청 금지, 같은 프로젝트 재등록 제한, 제목은 `서비스명 - 핵심 기능` 형식, 홍보성 표현은 제목이 아니라 본문에.

### 제목
`인수인계서 AI - 후임자 관점 꼬리질문으로 빈틈 찾기`
(가칭이므로 이름 확정 후 `{{ 이름 }} - 꼬리질문으로 인수인계서 빈틈 찾기`)

### 본문

```
공기업·공공기관에서 담당자가 바뀔 때 쓰는 인수인계서를 돕는 도구를 만들고 있습니다.
학생 팀(4명, 5주) 과제로 시작했고, 지금은 시제품 단계입니다.

▶ 바로 써보기: {{ 링크 }}
▶ 코드: {{ 저장소 URL }}

[왜 만들었나]
인수인계서는 서식 칸을 채우는 방식이라, 후임자가 실제로 막히는 지점이 빠집니다.
예외 처리, 승인 권한, 유관부서 연락 순서, 1년에 한 번 있는 일 같은 것들입니다.
기존 도구는 대부분 "이미 있는 문서를 잘 검색하는" 방향(RAG 챗봇, 문서 생성·표준화)이라,
문서 자체가 부실한 문제는 다루지 않습니다. 검색은 1회뿐이라 "없다"고 단정하지는 않습니다.

[무엇을 하는가]
1. 초안을 붙여넣으면 후임자 관점의 꼬리질문을 이어서 던집니다.
2. 대화가 끝나면 정리된 인수인계서와 "아직 답하지 못한 질문 목록"을 출력합니다.
3. 작성 가이드라인과, 확인이 필요한 약관·법규 지점을 근거와 함께 짚어줍니다.
   (법적 판단을 확정하는 기능이 아니라 검토 보조입니다.)

[기존 방식과 다른 점]
질문 목록을 제품 안에 숨기지 않고, 인수인계서 품질 체크리스트로 공개했습니다.
{{ 체크리스트 링크 }}
질문이 어디서 나왔는지 보이면 틀린 질문도 지적할 수 있다고 봤습니다.
체크리스트는 지금도 실무자 의견을 받아 고치는 중입니다.

[한계 — 먼저 말씀드립니다]
- 회사 자료를 쓸 수 없어 전부 가상 인수인계서로만 검증했습니다. 실제 조직 문서에서의 성능은 모릅니다.
- 문서에 없는 사실을 만들어내지 않도록 일부러 보수적으로 답합니다. 그래서 질문이 뻔해 보일 수 있습니다.
- 회사 메일 연동은 이번 범위에서 뺐습니다(한 달 안에 무리라고 판단).

[부탁]
"실무에서는 이 질문이 의미 없다", "이 항목이 더 자주 빠진다" 같은 지적이 가장 도움이 됩니다.
어떤 항목이 실제로 가장 자주 빠지는지가 아직 저희가 모르는 부분입니다.
```

**주의:** 댓글은 24시간 안에 답한다. 답변도 `experiment-log`에 남긴다. 업보트를 부탁하지 않는다(지인 포함).
